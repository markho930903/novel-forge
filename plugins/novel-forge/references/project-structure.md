# 小说项目目录契约

这份契约定义“保存/建项目”时的唯一目录形状。对话中的临时创作可以不落盘；一旦用户要求保存，就按此结构创建或补齐。稳定设计、设定资料、故事线和人物脉络要沉淀在固定文件中，不能只留在一次对话里。

## 标准目录

```text
小说项目/
+-- 00_一句话概览.md
+-- 核心蓝图/
|   +-- 核心蓝图.md
+-- 故事线/
|   +-- 故事线总表.md
|   +-- 主线.md
|   +-- 副线名称.md
+-- 大纲/
|   +-- 总纲.md
|   +-- 卷01/
|       +-- 卷纲.md
|       +-- 第001章_开篇.md       # 每章一个独立章节大纲
|       +-- 第002章_...md
+-- 设定/
|   +-- 世界观设定.md
|   +-- 人物角色.md
|   +-- 人物脉络.md
|   +-- 地图与地点.md
|   +-- 设定总览.md
|   +-- 重要角色/
|   |   +-- 主角.md
|   |   +-- 角色名.md             # 每个重要角色一个文件
|   +-- 人物档案/
|   +-- 地图/
|   +-- 专题/
+-- 06_图谱索引/                  # 分片机器可读事实源
|   +-- manifest.json             # schema、图例与计数
|   +-- nodes/char/protagonist.json
|   +-- edges/char/protagonist.json
|   +-- views/char/protagonist.md # 单节点局部图与出边表
+-- 06_图谱索引.md                # 紧凑类型级 Mermaid 概览
+-- 07_事实账本.md
+-- 08_创作合同.md
+-- 09_进度与待办.md
+-- 正文/
    +-- README.md
    +-- 卷01/
        +-- 第001章_开篇.md       # 与大纲/卷01/同名文件一一对应
```

初始化脚本会建立核心蓝图、主线、人物脉络和第一卷/第一章骨架；没有样章时可用 `--no-seed`，之后用 `add-volume`、`add-chapter`、`add-storyline` 补齐。`大纲/` 是大纲入口，`设定/` 是所有世界、人物、地图和专题设定的唯一资料根。

## 文件职责

| 文件/目录 | 必须回答的问题 | 更新时机 |
| --- | --- | --- |
| `00_一句话概览.md` | 主角、主动目标、独特阻力和代价是什么？ | 作品定位变化时 |
| `核心蓝图/核心蓝图.md` | 全书哪些命题、终局、不变量和主角弧不可随意改变？ | 稳定设计或终局变化时 |
| `大纲/总纲.md` | 全书主线如何起、转、收，分卷如何递进？ | 总纲或终局变化时 |
| `故事线/故事线总表.md` | 有哪些主线/副线，负责人、里程碑、交汇和回收是什么？ | 故事线新增、交汇或完结时 |
| `故事线/每条线.md` | 这条线的目标、阻力、证据、节点和终止条件是什么？ | 每次推进后 |
| `大纲/卷NN/卷纲.md` | 本卷从什么状态走向什么不可逆状态？ | 卷级目标、转折或回收变化时 |
| `大纲/卷NN/第NNN章_名称.md` | 本章如何推进故事线、蓝图和人物选择？章号至少三位，超过 999 后自然扩展。 | 每章规划和正文完成后 |
| `设定/世界观设定.md` | 世界如何运转，规则边界和代价是什么？ | 新规则首次确定或修订时 |
| `设定/人物角色.md` | 全部角色如何分层，谁拥有独立目标？ | 角色首次出现或关系改变时 |
| `设定/人物脉络.md` | 人物弧、关系网络和关键选择如何跨章节变化？ | 每次关系/弧线变化时 |
| `设定/重要角色/角色名.md` | 重要角色的身份、秘密、动机、限制和人物弧是什么？ | 角色事实变化时 |
| `设定/地图与地点.md` | 地点如何相连，移动需要什么成本？ | 新地点、路线或空间规则出现时 |
| `设定/设定总览.md`、`设定/专题/` | 势力、物件、制度、文化、技术和仪式如何影响选择？ | 设定会影响选择时 |
| `06_图谱索引/`、`06_图谱索引.md` | 节点如何通过人物、地点、势力、规则、线索、故事线和事件相连？ | 任何事实或关系变化后 |
| `07_事实账本.md` | 当前时间、位置、伤势、资源、线索状态是什么？ | 每章大纲定稿和正文完成后 |
| `08_创作合同.md` | 题材承诺、文风、视角和禁用项是什么？ | 开书或明确切换时 |
| `09_进度与待办.md` | 哪些层级已完成，下一步做什么？ | 每次交付后 |

## 核心蓝图

`核心蓝图/核心蓝图.md` 是全书的稳定设计层，至少沉淀一句话概览、核心命题、读者承诺、终局蓝图、主冲突引擎、世界不变量和主角弧线总览。章节可以改变细节，但不能无记录地违反不变量；需要改蓝图时先记录变更，再同步总纲、故事线和相关设定。

## 故事线

主线和每条副线都要有独立文件。故事线文件至少写起点、目标、阻力、失败代价、里程碑、交汇事件、证据、回收位置和终点条件。章节卡必须标出本章推进的故事线及状态变化；故事线总表只做索引，不替代独立文件。

## 人物脉络

`设定/人物脉络.md` 记录跨角色、跨章节的关系网络、人物弧阶段和关键选择链；`设定/重要角色/` 记录每个重要角色的事实档案。关系变化要有行动或信息证据，并同步故事线、章节卡、事实账本和图谱。

## 章节大纲

每一章节必须有独立 Markdown 文件，文件名为 `第NNN章_章节名.md`（章号至少三位，超过 999 后使用四位或更多位），直接放入对应的 `大纲/卷NN/`，与 `正文/卷NN/` 中的同名正文一一对应。一张卡至少包含：

- 章节在总纲、卷纲、核心蓝图和故事线中的作用；
- 起始时间、地点、已知信息、资源、伤势与限制；
- 本章目标、阻力、失败代价和关键选择；
- 场景顺序、每场的目标/阻力/行动/状态变化；
- 故事线推进、人物脉络影响、核心蓝图影响和图谱变更；
- 结尾状态、下一章压力和连续性检查。

不能用“第001-005章大纲.md”替代五个章节文件，也不能让正文先于章节卡产生关键新规则。

## 命名、链接与迁移

- 卷目录使用两位数字：`卷01`；章号使用三位数字：`第001章`，便于排序和检索。
- 文件名可以保留中文，但禁止 `/`、`\\`、冒号等路径分隔符。
- Markdown 链接使用相对路径；移动文件时同步更新链接和图谱分片中的来源。
- 图谱节点 ID 使用 ASCII 的 `type:slug`，故事线使用 `line:slug`，例如 `line:family-secret`。
- 事实状态用 `planned`、`active`、`resolved`、`retired` 等明确词，不把“可能”“应该”伪装成既定事实。
- 旧项目若已有根目录 `06_图谱索引.json`，先运行 `update_graph.py migrate` 拆分为目录；旧文件会保留为 `.legacy` 备份。若还存在 `大纲/核心蓝图.md`、`大纲/故事线/`，或根部设定文件与 `重要角色/`、`人物档案/`、`地图/`、`其他设定/`，再运行显式的 `migrate-layout`，然后用 `init --merge` 补齐新增蓝图、故事线和设定目录；确认链接和同名冲突后再删除旧空目录。
