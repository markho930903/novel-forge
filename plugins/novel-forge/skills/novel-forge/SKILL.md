# 小说创作工坊

把小说当作一组相互链接的事实、选择和文本来维护。始终同时守住三条底线：因果可追溯、表达自然流畅、内容原创。类型和文风可以改变读者体验，不能放宽事实约束。

## 先判断交付边界

- 只要临时创作或分析：默认在对话中交付，不写用户文件。
- 用户明确说“保存”“建项目”“落盘”“生成文件”或给出项目路径：先扫描已有项目，再按 [项目目录契约](references/project-structure.md) 写入。
- 用户要求清理、迁移或合并已有小说资料：先列出会影响的文件、事实和链接；正文已经写出的内容优先于旧大纲，不静默删除或覆盖。
- 用户只要正文：只输出正文，不附创作说明、自评、质量分数或“AI 痕迹”判断。

## 资料加载顺序

1. 先读项目现有的 `00_一句话概览.md`、`核心蓝图/核心蓝图.md`、`故事线/故事线总表.md`、`大纲/总纲.md`、`07_事实账本.md`、相关卷纲、章节大纲和正文；它们是当前作品事实源。
2. 根据主类型读取 [类型细则卡](references/genre-rules.md)，只加载相关卡片；未列出的类型按卡末的推导步骤建立规则。
3. 开书、写章、续写、改稿或审校时读取 [逻辑与文笔卡](references/prose-quality.md)；已有文风合同则以 `08_创作合同.md` 为准，否则读取 [文风卡](references/style-profiles.md) 推导一份合同。
4. 需要新增或查询人物、地点、势力、规则、线索、事件或物件时读取 [图谱索引规范](references/graph-index.md)。

## 新建或补齐项目

显式要求落盘时，优先使用随技能提供的标准脚本，不手工发明另一套目录：

```bash
python3 scripts/init_novel_project.py init ./小说项目 \
  --title "作品名" \
  --one-line "主角为了目标，在独特阻力下付出代价的一句话概览" \
  --genre "主类型" --style "主文风"
```

脚本默认建立根资料、`核心蓝图/`、`故事线/`、`大纲/`、`设定/` 及其子目录、第一卷卷纲、第一章独立章节大纲和对应正文文件。已有项目只补缺失文件时使用 `--merge`；不要用 `--force` 覆盖正文。之后：

```bash
python3 scripts/init_novel_project.py add-volume ./小说项目 --number 2 --name "卷名"
python3 scripts/init_novel_project.py add-chapter ./小说项目 --volume 2 --number 1 --name "章节名"
python3 scripts/init_novel_project.py add-role ./小说项目 --name "角色名" --important --id char:role-slug
python3 scripts/init_novel_project.py add-storyline ./小说项目 --id line:side-quest --name "副线名称"
python3 scripts/init_novel_project.py migrate-layout ./小说项目
python3 scripts/validate_novel_project.py ./小说项目
```

每一章必须有且只有一个对应的 `大纲/卷NN/第NNN章_名称.md`；卷纲是同一卷目录中的 `大纲/卷NN/卷纲.md`，正文文件与章节大纲同名但可以暂为空。重要角色必须各自拥有 `设定/重要角色/角色名.md`，`设定/人物角色.md` 只做索引。脚本只生成骨架，事实、选择和文字仍需根据用户设定填写。

## 必须维护的创作层级

### 一句话概览

用一个可复述的句子同时包含主角、主动目标、独特阻力和代价/悬念。它放在 `00_一句话概览.md`，总纲和对外简介引用同一句；概览变化时留下版本记录，不让正文悄悄漂移。

### 核心蓝图与故事线

`核心蓝图/`、`故事线/` 和 `大纲/` 必须是项目根目录下的同级目录。核心蓝图只保存全书稳定设计、终局、不变量和主角弧；故事线总表与每条独立故事线文件保存跨章节因果链。总纲、卷纲和章节卡通过相对链接引用它们，不能把核心蓝图或故事线重新塞进 `大纲/`。

### 总纲与分卷

总纲回答全书的主题命题、主线因果、读者承诺、终局问题和分卷递进。每卷独立文件，写清卷级目标、起始/终止状态、核心转折、人物弧、章节范围和线索回收。卷纲不能只列事件名，要说明“选择如何造成下一状态”。

### 章节大纲

每章卡必须写：章节定位、视角与起始状态、本章目标、阻力、失败代价、关键选择、场景顺序、结尾状态、线索推进、图谱变更和连续性检查。章节卡直接放在所属卷目录中，不能再建立平行的“章节大纲”根目录。场景表至少有目标、阻力、行动和状态变化；没有选择或状态变化的场景应删掉或合并。规划多章时也要逐章落成文件，不能用范围标题代替。

### 世界观、人物、地图与设定

- 世界观：每条核心规则写触发条件、可知信息、限制、代价、后果和首次建立章节。
- 人物：主角和重要角色写欲求、缺口、秘密、信息边界、关系、能力/资源限制、关键选择与人物弧；配角只有拥有独立目标且能改变情节时才扩写。
- 地图：登记区域、地点、相对位置、距离/耗时、进入条件、资源和路线阻力；移动不能凭情节方便瞬移。
- 设定：所有会影响人物选择或连续性的势力、制度、物件、文化、技术、仪式等统一收纳在 `设定/`，并为可复用内容建立稳定 ID。

## 图谱索引工作流

`06_图谱索引.json` 是事实源，`06_图谱索引.md` 是可读视图。新节点先登记，再建立关系；每条关系至少有来源、证据、首次出现、状态，悬疑线还要有计划回收位置。任何正文或大纲造成的人物关系、地点移动、规则触发、线索状态或事件因果变化，都要同步图谱和事实账本。

用脚本维护并重新渲染：

```bash
python3 scripts/update_graph.py add-node ./小说项目 --id rule:three-bells \
  --type rule --name "三声钟响" --source "设定/世界观设定.md#核心规则"
python3 scripts/update_graph.py add-edge ./小说项目 --from rule:three-bells \
  --relation "触发" --to event:door-opens --evidence "第002章第三声后门锁松动" \
  --first-seen "第002章" --payoff "第008章" --source "大纲/卷01/第002章_钟声.md"
python3 scripts/update_graph.py render ./小说项目
```

反转时保留旧边和旧证据，把状态改为 `resolved` 或 `retired`，再添加新的真实关系。不得把作者知道但读者从未见过的事实当作公平线索。

## 开书、写作与审校模式

### 开书

先给创作合同：一句话概览、命题、主冲突、读者承诺、视角、主角欲求与代价、核心规则、主/辅助类型、主/辅助文风和禁用项。然后按用户要求扩展世界观、重要角色、地图、总纲、卷纲和第一章卡；缺少决定性信息时最多追问一个问题，其余用显式假设推进。

### 写章与续写

先确认上一章结尾状态和本章卡，再写正文。场景冲突必须来自人物欲求、环境限制或已建立规则；角色只能使用其当时知道的事实。结尾留下由本章行动产生的压力，不用口号式悬念。正文完成后更新事实账本、图谱和进度。

### 改稿与审校

按顺序报告并修复：硬性事实/因果矛盾，信息与动机问题，节奏和场景功能，文风偏离，重复词句与标点。指出具体文件、章节或段落及可替换方案；不要以“更有文采”替代修改。

## 类型与文风闸门

主类型最多叠加两个辅助类型。每增加一套力量或制度体系，都登记边界、代价和交互规则，并在章节卡中兑现主类型承诺。主文风决定语体、叙述距离和整体节奏，最多一个辅助文风；切换要记录生效的卷、章节或场景。用户提及作品名时只转译高层机制，绝不复用角色、地名、专名、剧情、章节结构或原文表达。

## 交付前硬检查

- 一句话概览、总纲、当前卷纲和章节卡没有互相冲突。
- 规则、能力、资源、时间、地点、伤势、人数、金额、距离和库存可逐项复算。
- 每个角色依据已知信息和稳定动机行动；每个关键反转有此前出现的证据。
- 每个章节有目标、阻力、选择和结尾状态变化；图谱来源能回到资料或正文。
- 正文每段至少推进人物、冲突、氛围或线索之一；对白有目的、信息差或关系压力。
- 运行 `validate_novel_project.py`；脚本/插件修改后再运行官方插件和技能校验。

逻辑有缺口时补因果、降低承诺或删改冲突，不用华丽描写掩盖。不得声称能绕过检测器，也不得输出虚构的“AI 痕迹评分”。
